# LRCore Cloud Platform - 部署与运维规范

## 1. 规则概述

### 1.1 文档目的

本文档定义了 LRCore Cloud Platform 项目的服务部署流程、环境配置、监控维护和终端使用管理规则。

### 1.2 适用范围

适用于运维人员和开发人员。

### 1.3 执行原则

- **严格遵守**：所有部署运维活动必须严格遵守本规则
- **可追踪性**：确保所有操作可追溯
- **安全性**：保障服务操作的安全性

## 3. 部署流程

### 3.1 构建流程

1. 执行 `mvn clean package` 构建后端服务
2. 执行 `npm run build` 构建前端项目

### 3.2 部署步骤

1. 停止旧服务
2. 备份配置文件
3. 上传新构建的 JAR 包
4. 启动新服务
5. 验证服务状态

### 3.3 容器化部署

- 使用 Docker 容器化
- 使用 Docker Compose 编排服务
- 配置健康检查和自动重启

## 5. 终端使用管理规则

### 5.1 终端使用基本原则

1. **单一终端原则**：所有后端SpringBoot服务在执行任何运维操作时，必须严格限定在**同一个终端窗口**内进行
2. **禁止并发操作**：严禁同时打开多个终端窗口对同一服务执行startup、shutdown、restart等任何运维操作
3. **操作归属明确**：每个服务的运维操作应在固定的终端窗口中进行，确保操作来源可追溯

### 5.2 操作类型定义

| 操作类型 | 说明 | 终端要求 |
|---------|------|---------|
| startup（启动） | 启动SpringBoot服务 | 必须在单一终端窗口内执行 |
| shutdown（停止） | 停止SpringBoot服务 | 必须在单一终端窗口内执行 |
| restart（重启） | 重启SpringBoot服务 | 必须在单一终端窗口内执行 |
| log（日志查看） | 查看服务运行日志 | 建议在操作服务的同一终端窗口 |
| debug（调试） | 调试模式启动服务 | 必须在单一终端窗口内执行 |

### 5.3 适用范围

**环境范围**：
- 开发环境（development）
- 测试环境（test）
- 生产环境（production）

**服务范围**：
- 所有SpringBoot微服务实例
- 包括但不限于：网关服务、认证服务、系统服务、文件服务、订单服务等

**人员范围**：
- 开发人员
- 测试人员
- 运维人员（DBA、DevOps工程师等）

### 5.4 操作记录保存方式

1. **日志记录**：
   - 所有运维操作必须记录到服务日志中
   - 日志内容应包含：操作时间、操作类型、操作人员、服务实例、环境信息、结果状态

2. **操作审计**：
   - 保留最近90天的运维操作记录
   - 生产环境操作记录保留期限不得少于6个月
   - 操作记录应支持查询和导出功能

3. **记录格式**：
   ```
   [时间戳] [环境] [服务名] [操作类型] [操作人员] [终端信息] [结果]
   示例：[2026-04-23 10:30:15] [dev] [lrcore-system] [startup] [zhangsan] [terminal-001] [SUCCESS]
   ```

### 5.5 违规监控机制

1. **实时监控**：
   - 检测是否存在同一服务在多个终端窗口并发执行运维操作的情况
   - 检测是否存在未授权的运维操作
   - 监控终端与服务实例的绑定关系

2. **告警机制**：
   - 触发违规操作时，系统自动发送告警通知
   - 告警通知对象：违规操作人员及其直属上级
   - 告警方式：邮件、短信或即时通讯工具

3. **违规处理**：
   - 首次违规：口头警告并记录在案
   - 二次违规：书面警告，要求提交书面检查
   - 累计违规：暂停运维操作权限，进行培训考核

4. **监控工具**：
   - 使用Spring Boot Admin进行服务状态监控
   - 使用Nacos进行服务注册与发现监控
   - 使用ELK Stack进行日志收集与监控分析

### 5.6 培训与考核

1. **培训要求**：
   - 所有开发、测试及运维人员在上岗前必须接受终端使用管理规则培训
   - 培训内容：规则要求、违规案例、操作规范
   - 培训时长：不少于2小时

2. **考核机制**：
   - 培训结束后进行规则考核，考核通过后方可获得运维操作权限
   - 考核内容：规则理解、场景判断、实际操作
   - 定期进行规则复训和考核（每季度一次）

3. **持续教育**：
   - 定期发布违规案例通报，进行警示教育
   - 收集并分析规则执行过程中的问题，持续优化规则内容
   - 鼓励人员提出改进建议，完善终端使用管理机制
