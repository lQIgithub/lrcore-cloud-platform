# LRCore Cloud Platform - 安全规范

## 1. 规则概述

### 1.1 文档目的

本文档定义了 LRCore Cloud Platform 项目的安全规范，包括认证授权、数据安全、接口安全等方面的规则。

### 1.2 适用范围

适用于所有开发人员和运维人员。

### 1.3 执行原则

- **严格遵守**：所有安全相关活动必须严格遵守本规则
- **保密性**：保护敏感信息不泄露
- **完整性**：确保数据不被篡改

---

## 2. 认证与授权

### 2.1 认证机制

- 使用 JWT 进行身份认证
- 登录认证通过 `lrcore-auth` 模块处理
- Token 有效期设置合理（默认 2 小时）

### 2.2 授权机制

| 注解 | 用途 | 说明 |
|-----|------|------|
| `@RequiresPermissions` | 权限控制 | 验证用户是否具有指定权限 |
| `@RequiresRoles` | 角色控制 | 验证用户是否具有指定角色 |
| `@RequiresLogin` | 登录验证 | 验证用户是否已登录 |
| `@InnerAuth` | 内部接口认证 | 验证接口是否为内部调用 |

### 2.3 权限管理

- 基于 RBAC（基于角色的访问控制）模型
- 权限粒度控制到按钮级别
- 定期审计权限配置

---

## 3. 数据安全

### 3.1 数据加密

- 敏感数据（如密码）使用 MD5 加密
- 配置信息使用加密存储
- 传输数据使用 HTTPS

### 3.2 数据脱敏

- 敏感字段使用 `@Sensitive` 注解进行脱敏
- 日志中避免记录敏感信息
- 接口返回数据进行适当脱敏

### 3.3 SQL 注入防护

- 使用 MyBatis-Flex 防止 SQL 注入
- 避免直接拼接 SQL 语句
- 使用参数化查询

**参考**: [rules-backend.md](./rules-backend.md) - MyBatis-Flex 使用规范

---

## 4. 接口安全

### 4.1 接口防护

- 实现请求频率限制
- 实现接口幂等性校验
- 实现接口签名验证

### 4.2 XSS 防护

- 使用 `XssFilter` 过滤恶意脚本
- 前端输入进行验证和转义
- 后端输出进行 HTML 转义

### 4.3 CSRF 防护

- 实现 CSRF Token 验证
- 验证请求来源
- 限制跨域请求

## 5. 异常处理安全

### 5.1 异常类型定义

| 异常类 | 描述 | 使用场景 |
|-------|------|---------|
| ServiceException | 业务逻辑异常 | 业务规则验证失败 |
| GlobalException | 全局异常 | 系统级错误 |
| CaptchaException | 验证码异常 | 验证码验证失败 |
| InnerAuthException | 内部认证异常 | 内部接口调用认证失败 |
| PreAuthorizeException | 权限异常 | 权限验证失败 |

### 5.2 异常处理流程

1. **异常捕获**：
   - Controller 层使用 `@RestControllerAdvice` 统一捕获异常
   - Service 层捕获业务异常，转换为 `ServiceException`

2. **异常处理**：
   - 记录异常日志（使用 `log.error`）
   - 转换异常为标准响应格式
   - 返回适当的 HTTP 状态码

3. **异常响应格式**：
   ```json
   {
     "code": 500,
     "msg": "操作失败",
     "data": null
   }
   ```

**参考**: [rules-backend.md](./rules-backend.md) - 异常处理规范
